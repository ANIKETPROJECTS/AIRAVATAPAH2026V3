I have already developed the admin-side web application. Now, I need to build a mobile application for the farmer side using React Native (via Replit’s mobile development environment).

The mobile application must be created inside a single, separate folder placed at the root of the project. This folder must contain the complete mobile app, including UI, logic, API integrations, and state management. It should be fully self-contained so that if I copy this folder alone into another environment (such as Replit or VS Code), it should run independently without requiring additional configuration.

Currently, there is a “Farmer App Preview” module built using web technologies as a dummy/mock interface. I now want to create a real mobile implementation called “Original Mobile App” using React Native. This should exist alongside or below the preview module and represent an actual working mobile application.

The mobile app must have a different name and logo so it can be clearly distinguished from the web application.

The core functionality of the mobile app should follow this workflow:

The farmer should be able to register without manually entering any data. Instead, the farmer will upload five required documents (the same documents used in the existing “New Registration” module).

Once uploaded, the backend will process these documents using OCR via an API to extract relevant data automatically. This extracted data will then be sent to the admin panel and stored in the Farmer Registry.

On the admin side, the admin will review the extracted data and can verify, accept, or reject the farmer.

After verification:

* If approved, the farmer should receive a notification in the mobile app, their profile should be generated, and they should become eligible to apply for schemes, insurance, and subsidies.
* If rejected, the farmer should receive an appropriate status update or feedback in the mobile app.

The mobile app must include clear status tracking (Pending, Approved, Rejected) and notification handling after admin actions.

The overall goal is to build a fully functional, production-ready mobile application that integrates seamlessly with the existing backend and admin system, while remaining modular, portable, and independently runnable.
